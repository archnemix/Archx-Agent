# Local API trial — OpenRouter, xAI, Gemini

This build contains a **prototype** explicit-send Chat path. The three-OS CI run `43482937372` compiled and tested its synthetic request builder, but **did not access a real OS credential store or call a provider**. Do not assume a provider works until you run this on your own machine. Never paste keys, prompts, response bodies or screenshots with revealed keys into issues/chat. The Windows executable in `deliverables/Unreleased/windows/archx-ai-lab.exe` is **unsigned**; download only from this repository's branch if you choose to trial it. Don't override a security warning merely because this guide exists.

## Before a test

1. Check the provider's current model documentation, privacy terms and pricing yourself. A displayed `:free` OpenRouter ID is a **distinct model variant**, not a promise that every request is free. Choose a model you are willing to test. No catalog, price lookup or account-usage check is implemented yet.
2. Launch a single copy of the Lab in your normal, unlocked desktop session. Linux requires an available/unlocked Secret Service; if it is unavailable the app **fails closed** rather than saving plaintext. Multiple simultaneous Lab instances have no cross-process vault-index transaction lock; avoid editing keys from two copies at once.
3. Open **Settings → Connections**, choose provider, paste a key into the masked field, then **Save key to OS vault**. The field clears; numbered key slots appear after the OS-store task completes. Do not reveal a key during screen sharing. Reveal/Hide acts only in the current UI; a same-user process or screen recorder can still observe data.
4. Open **Settings → Models**, choose the *same provider*, type a provider-issued model ID and Add model. Model selection is **session-only**, so choose it again after reopening the app. Multiple OS-vault keys for one provider rotate on successive explicit calls. If you delete a key while a request is in flight, it may already be in an HTTP authorization header.
5. Optional **Run small generation test**: this sends only `Reply with the word OK.`; requested response cap is 256 output tokens. **This may be billed.** The app reports success if a plain-text reply was parsed but deliberately does not show or persist that test reply. Total input/output tokens and charges cannot be guaranteed by the app. A transport timeout can occur *after* provider processing; don't blindly retry.
6. Open **Agent → Chat**, type a short non-sensitive message, and click **Send**. This sends the message plus up to 11 preceding turns from that draft to the selected provider over a fixed HTTPS endpoint. Enter does not submit; other modes cannot send or use tools. If the request fails, the unsent text is restored for an *explicit* retry and is not silently resent as history.

A failure can be reported as **provider, manually selected model ID (if not sensitive), operating system, and the generic UI status/HTTP status code only**. Do not share the API key or chat text. An HTTP 401/403 suggests key or account permissions; a 404 can indicate a model ID/endpoint mismatch; a network error does not prove the key is invalid. Success with a short synthetic prompt shows this particular model/key/endpoint worked at that moment—not all providers/models or availability over time.

## Limits

No persistent chat history, database, agent tools, uploads, search, cloud sync or long-term memory is enabled. Chats and model selections exist only in this process; provider and OS components may retain data according to their own policies. The OS vault protects keys at rest but not against malware in the unlocked session or all copies made in UI/HTTP/TLS memory. Timed reveal is an app-level display deadline, not a guarantee that OS/renderer copies are wiped exactly at 15 seconds. Provider catalog, usage/availability checks and real three-OS keychain/interaction evidence remain future work.
