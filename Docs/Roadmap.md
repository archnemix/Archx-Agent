## Shared completion rule

For each GUI-bearing step: demonstrate the finished behavior, run relevant unit/integration checks on Linux, Windows, and macOS, record test inputs/outputs, and make a **downloadable Windows build** available for the user to run before continuing. Do not claim cross-platform success from compilation alone; check the user-facing flow on each target where feasible. Settle a sustainable Windows-download delivery method before Step 1 (store required workflow logs/results in the repository; avoid filling Git history with large binaries). If the build or tests fail, fix them before the next step. Documentation-only planning is not a GUI step.

## Ordered steps

0. **Prepare only the home-screen slice — done.** The user named the launcher Archx AI Lab and chat destination Archx Agent, described the AI/ML launcher layout and graphite style, chose repository-hosted Windows builds, and requested three-OS screenshots. The visual criteria are in `Docs/design.md`; Iced 0.14 API sources are in `Docs/Research.json`. Do **not** block the home screen on model, memory, or tool decisions; resolve those just before the steps that need them.
1. **Home screen and app shell.** Build the Iced desktop window, intentional home layout, navigation structure, and clear entry cards for AI chat and future superapp areas. Unbuilt actions are labeled unavailable, not simulated. The latest design review asks for **animated typographic artwork** in the Agent hero and shelf, not the old image or a 3D asset; Training and Fine-tuning use prominent hover-cycling workbench words with phase markers, while Model Monitor is hidden. The supplied Archnemix sidebar mark must be smaller and retain transparency. Validate distinct Agent animation phases and initial/hover states on all three OSes; still screenshots alone cannot prove full animation smoothness. Windows verified-publisher signing remains an external prerequisite, not a metadata checkbox. Verified Windows publisher signing is a separate external prerequisite: first establish an identity-validated certificate and secure signing path, then verify the actual signature; do not claim it from metadata. Done when the home screen behaves correctly on all three operating systems, a downloadable Windows build is provided, and the user accepts the design.
2. **Chat interface and mode navigation.** Build the UI-only conversation workspace, six-mode selector, in-session draft navigation, and navigation between the Lab and Agent. Introduce shared Lab Settings with Memory Light/Heavy/Custom *preview* only; do not claim persistence or RAM behavior until real resources exist. Define mode-specific UI boundaries; unavailable mode actions stay disabled. Decide whether allowed conversions fork linked chats or mutate one, then implement only UI/state behavior that is meaningful at this stage. Done when navigation and local UI state behave correctly, without implying an AI backend exists, and the three-OS/Windows-build gate passes.
3. **Provider configuration and safe connection tests.** Add shared Settings for OpenRouter, xAI Grok and Gemini, multiple keys per provider in OS-backed secure storage, opt-in model catalog and manual IDs, add/remove selection, masked keys and bounded reveal, explicit provider-aware connection tests and error handling. Do not silently route a free model to a paid fallback. Decide a realistic memory/secret threat model and test-budget semantics before implementation. Use mock contract tests in three-OS CI and require user-initiated live verification with locally entered keys; do not claim real provider access from this sandbox. Done when safe UI/credential handling and honest test results meet the cross-OS gate.
4. **Simple chat, end to end.** First agree on model choice, persistent-write consent, and storage boundary. Then send/receive and display responses, handle cancellation/errors, persist and reopen ordered conversations, and provide context-budget/summary behavior. Add internet search only with an agreed search source and permission model. Done when one complete chat journey works, recovers predictably, and passes the shared gate.
5. **Shared agent and memory foundation.** First agree on tool permissions and memory scope rules. Then implement approved memory scopes, selective retrieval, provenance and consent controls, stable profile/settings, and a centralized permission boundary for tools. Add only infrastructure required by the next mode, not speculative providers or storage engines. Done when the next mode can reuse these facilities without bypassing consent or losing archive fidelity, with the shared gate met.
6. **General task agent.** Add the newly requested agentic mode for non-specialized tasks, with its actual tool set and permissions agreed before implementation. No silent broad machine access. Done when a representative permitted task completes, denied actions stay blocked, memory is traceable, and the shared gate passes.
7. **Research agent.** Add source-backed deep research, provenance, retrieval, and its own memory. Implement eligible simple-chat → research transition while preserving original history. Done when a research task can be inspected and resumed, and the shared gate passes.
8. **Coding agent.** Add project indexing, file/interface/flow lookup, scoped code tools, execution/test/publish approvals, and project memory. Implement eligible simple-chat/research → coding transitions with explicit history/state rules. Done when a bounded coding task can be inspected, run, tested, and recovered safely, and the shared gate passes.
9. **Learning agent.** Add interactive lessons, goals, assessments, progress, and learning memory. Implement eligible simple-chat → learning transition. Done when a learner can complete and resume a scoped lesson, and the shared gate passes.
10. **Play agent.** Add controlled game creation, explicit game state, user/agent turn loop, and conversational play. Implement eligible simple-chat → play transition; never run generated code without agreed isolation/approval. Done when one game can be played, paused, and resumed safely, and the shared gate passes.
