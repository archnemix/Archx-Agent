**Status: Step 0 done; Step 1 Agent-type and transparent-logo revision technically validated by three-OS run `43200600325` (six tests per OS, Home/About and frozen animation states). ## Shared completion rule

For each GUI-bearing step: demonstrate the finished behavior, run relevant unit/integration checks on Linux, Windows, and macOS, record test inputs/outputs, and make a **downloadable Windows build** available for the user to run before continuing. Do not claim cross-platform success from compilation alone; check the user-facing flow on each target where feasible. Settle a sustainable Windows-download delivery method before Step 1 (store required workflow logs/results in the repository; avoid filling Git history with large binaries). If the build or tests fail, fix them before the next step. Documentation-only planning is not a GUI step.

## Ordered steps

0. **Prepare only the home-screen slice — done.** The user named the launcher Archx AI Lab and chat destination Archx Agent, described the AI/ML launcher layout and graphite style, chose repository-hosted Windows builds, and requested three-OS screenshots. The visual criteria are in `Docs/design.md`; Iced 0.14 API sources are in `Docs/Research.json`. Do **not** block the home screen on model, memory, or tool decisions; resolve those just before the steps that need them.
1. **Home screen and app shell.** Build the Iced desktop window, intentional home layout, navigation structure, and clear entry cards for AI chat and future superapp areas. Unbuilt actions are labeled unavailable, not simulated. The latest design review asks for **animated typographic artwork** in the Agent hero and shelf, not the old image or a 3D asset; Training and Fine-tuning use subtle text hover, and Model Monitor is hidden. The supplied Archnemix sidebar mark must be smaller and retain transparency. Validate distinct Agent animation phases and initial/hover states on all three OSes; still screenshots alone cannot prove full animation smoothness. Windows verified-publisher signing remains an external prerequisite, not a metadata checkbox. Verified Windows publisher signing is a separate external prerequisite: first establish an identity-validated certificate and secure signing path, then verify the actual signature; do not claim it from metadata. Done when the home screen behaves correctly on all three operating systems, a downloadable Windows build is provided, and the user accepts the design.
2. **Chat interface and mode navigation.** Build the conversation UI, mode selector, and navigation between home and chats. Define mode-specific UI boundaries; unavailable mode actions stay disabled. Decide whether allowed conversions fork linked chats or mutate one, then implement only UI/state behavior that is meaningful at this stage. Done when navigation and local UI state behave correctly, without implying an AI backend exists, and the three-OS/Windows-build gate passes.
3. **Simple chat, end to end.** First agree on initial model source and local/remote execution, persistent-write consent, and storage boundary. Then connect the model, send/receive and display responses, handle cancellation/errors, persist and reopen ordered conversations, and provide the needed context-budget/summary behavior. Add internet search only with an agreed search source and permission model. Done when one complete chat journey works, recovers predictably, and passes the shared gate.
4. **Shared agent and memory foundation.** First agree on tool permissions and memory scope rules. Then implement approved memory scopes, selective retrieval, provenance and consent controls, stable profile/settings, and a centralized permission boundary for tools. Add only infrastructure required by the next mode, not speculative providers or storage engines. Done when the next mode can reuse these facilities without bypassing consent or losing archive fidelity, with the shared gate met.
5. **General task agent.** Add the newly requested agentic mode for non-specialized tasks, with its actual tool set and permissions agreed before implementation. No silent broad machine access. Done when a representative permitted task completes, denied actions stay blocked, memory is traceable, and the shared gate passes.
6. **Research agent.** Add source-backed deep research, provenance, retrieval, and its own memory. Implement eligible simple-chat → research transition while preserving original history. Done when a research task can be inspected and resumed, and the shared gate passes.
7. **Coding agent.** Add project indexing, file/interface/flow lookup, scoped code tools, execution/test/publish approvals, and project memory. Implement eligible simple-chat/research → coding transitions with explicit history/state rules. Done when a bounded coding task can be inspected, run, tested, and recovered safely, and the shared gate passes.
8. **Learning agent.** Add interactive lessons, goals, assessments, progress, and learning memory. Implement eligible simple-chat → learning transition. Done when a learner can complete and resume a scoped lesson, and the shared gate passes.
9. **Play agent.** Add controlled game creation, explicit game state, user/agent turn loop, and conversational play. Implement eligible simple-chat → play transition; never run generated code without agreed isolation/approval. Done when one game can be played, paused, and resumed safely, and the shared gate passes.

## Later or conditional work

Optional embeddings, remote backup providers, MCP integrations, further superapp modules, and distribution/update channels need their own agreed, testable steps when their requirements are known. They are not silently included in the initial steps. Mode order from Step 5 onward is a proposal: the user may reprioritize it, provided prerequisites and the completion gate remain intact.
