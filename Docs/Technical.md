# Technical overview

Iced is the selected Rust desktop UI framework; Windows, macOS, and Linux are first-class targets from the start. The native launcher is implemented, but no AI provider, agent runtime, persistence engine, or product backend has been selected or built. See [Files_Info.json](Files_Info.json) for each file's responsibility and inputs/outputs, [Logic.md](Logic.md) for implemented call flows, and [Plan/Architecture.md](Plan/Architecture.md) for discussed product behavior. Keep these aligned as components are added.

## Home shell in progress

- `Cargo.toml`: Rust 2024 application with Iced 0.14 for native UI and `image` 0.25 PNG support only for opt-in cross-OS screenshot capture. The latest Agent-type follow-up passed six focused tests, release builds, Home/About, two Agent-phase and three model-hover-phase captures on each of Linux, Windows and macOS; Windows CI also verified PE GUI subsystem 2 (no console) and truthful product metadata. See `Test_Results/Unreleased/Gui_Validation.md`. This does not establish future agent functionality or pixel-identical UI rendering.
- `src/main.rs`: initializes the window, Manrope on all OSes and Space Grotesk static instances only on Linux/Windows (macOS font-weight rendering fallback), native icon, theme, and application callbacks; Windows **release** builds select the GUI subsystem so launching the app does not open a console.
- `src/app.rs`: holds home/about navigation and opt-in `ARCHX_SNAPSHOT` capture state. `ARCHX_SNAPSHOT_PAGE=about` selects About; `ARCHX_SNAPSHOT_HOVER=training|tuning` with `ARCHX_SNAPSHOT_PHASE=0|1|2` freezes a model-text phase, and `ARCHX_SNAPSHOT_AGENT_PHASE=0..5` freezes an Agent mode for CI only. On Home, a 1500ms timer advances Agent kinetic type; a hover-only 700ms timer advances one of three conceptual Training/Tuning stage highlights and stops on exit/About. Snapshot delay remains five seconds. No model or persistence yet.
- `src/home.rs`: renders the AI Lab launcher, animated Agent feature and About view with the smaller transparent sidebar mark; unfinished destinations are inert.
- `src/agent_visual.rs`: renders the Agent's native gradient/kinetic text feature and shelf panel, sharing one six-mode phase; tests mode labels and wraparound. No generated cover image remains.
- `src/app_tile.rs`: renders Agent and two unavailable model labs. Model Forge and Refinement Studio put a changing 35px display word and three-part marker at the visual center on hover; the labels are concepts, not live work. Tests check distinct three-stage language. Model Monitor stays hidden.
- `build.rs`: embeds the user-supplied Archnemix ICO and company metadata only on Windows. The metadata is not a digital signature.
- `src/style.rs`: semantic black/silver colors, higher-contrast muted text, font-role constants (Manrope Normal-only on macOS) and major spacing steps aligned with `Docs/design.md`, including a native selected-menu pill. `assets/fonts/` holds licensed Manrope and Space Grotesk; `assets/brand/` holds the supplied transparent sidebar mark and native icon derivatives.
- `.github/workflows/gui.yml`: source-triggered three-OS compilation/test/screenshot review and repository-hosted portable Windows executable. The local sandbox has no Rust toolchain; run `43200600325` supplies Agent typography, transparent-sidebar and model hover-state build/runtime evidence. Its still screenshots do not validate physical mouse movement, 3D Agent animation or native window chrome, and the unsigned binary cannot show a verified publisher.

## Step 2 UI-only shell

- `src/agent.rs`: renders Agent's inner draft rail, six preview mode buttons, empty state and an editable **unsent-only** composer with no Send event. Input is the App's transient `Vec<ChatDraft>` and selection; output is Iced `Element<Message>`; it performs no model calls or disk writes.
- `src/settings.rs`: renders the global Lab Settings page with Memory Light, Memory Heavy and Custom preview choices and the Agent-only Custom choice. Input is transient UI preference state; output is Iced events only; it neither saves a preference nor claims to manage RAM.
- `src/app.rs` owns navigation between Home, Agent, Settings and About, in-session draft IDs/text and selected mode, and UI-only memory selections. Invalid draft IDs and mode indexes are ignored; edits target the currently selected draft ID only. No text is sent or persisted. `src/home.rs` hosts the shared rail and dispatches views; model-cover visuals remain unchanged.

- Shared rail density: `src/app.rs` stores session-only `sidebar_expanded` and handles `ToggleSidebar`; `src/home.rs` renders 220px expanded and 84px compact rail with labelled navigation and transparent mark. The Agent workspace remains a separate inner rail. `ARCHX_SNAPSHOT_SIDEBAR=collapsed` captures deterministic alternate layout only in screenshot mode.

- `src/credentials.rs`: native OS-backed provider-key vault foundation. `Provider` scopes OpenRouter/xAI/Gemini, `Vault<OsStore>` uses `keyring` 4.2's Keychain/Credential Manager/Secret Service v1 adapter with no plaintext fallback, and `with_key` bounds a retrieved `Zeroizing<String>` to a callback. Per-provider key ID index is stored in the same OS vault, not in a plaintext app config. Fake-store tests exercise state and redaction without touching a user OS vault. No Settings key UI, networking or provider tests are wired yet.

- `src/home.rs` bottom-anchors the rail collapse/expand affordance in either width while leaving the accepted Agent typography and app previews unchanged. `src/style.rs::rail_toggle` has a neutral style distinct from the silver active destination.

- `src/provider_api.rs` constructs one fixed-origin HTTPS POST for OpenRouter/xAI chat-completions or Gemini generateContent; accepts user/assistant text only, a manually selected model ID (validated against path/query injection), 12 or fewer turns, 256 requested output tokens and at most 64 KiB returned JSON. No tools or uploads; no automatic retry/redirect/proxy; provider error body and reqwest error are discarded. The frontend `App::send_chat` chooses a credential ID round-robin in a background OS-vault lookup then dispatches `provider_api::send` only after an explicit Send or small generation-test click. Live API access is **unverified**.
- `src/settings.rs` provides three navigable settings pages. Provider keys are masked on entry and listed as numbered slots, stored in OS vault; explicit reveal has a timed UI deadline. Model IDs and selection are session-only. There is no catalog, account-statistics call, persistent conversation archive, database or model memory. Iced input/renderer and reqwest may retain plaintext copies despite zeroization of app-owned allocations.

- Settings operations mark a per-window key-busy flag during add/remove so a second click or provider switch cannot overlap an index mutation. This does **not** provide cross-process transactions for multiple simultaneous Lab instances; a future index-locking or per-item enumeration strategy is needed before promising robust concurrent key management. Reveal now offers Hide to discard the app-owned key immediately. A disabled button uses a distinct dark state instead of looking actionable.

- `src/navigation.rs` owns two distinct native Iced render trees selected by session-local `App::sidebar_expanded`: expanded icons+text at 220px and compact icon-only at 92px. Embedded local Lucide SVG bytes render with `iced`'s `svg` feature, selected/icon-state color filters and right-positioned `tooltip`; no runtime icon fetch. The transparent bundled Archnemix image remains the brand. `src/style.rs` defines compact 52px selection, Settings section selection and tooltip/divider roles. `src/home.rs` delegates global rail rendering to this module; accepted Agent kinetic artwork is not changed. `src/settings.rs` uses a 190px section navigation panel plus one scrollable active detail panel; existing actions stay wired.
