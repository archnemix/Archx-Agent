# Archx Agent 1.9.0 ↔ native Iced: functionality and UI audit

## Evidence and scope

**Reference:** the complete user-supplied 1.9.0 tar at `internels/reference/web/archx-agent/`, particularly `public/index.html`, `public/js/{ui,chat,blocks,render,state}.js`, `public/css/`, `lib/server.js` and `UI-RULES.md`. **Native:** `src/{app,agent,settings,provider_api,model_catalog,custom_endpoint,credentials,home}.rs`. This is a source-backed feature inventory, not an assertion that all reference features have been ported or tested against real vendors. The web app is only a comparison target; it does not run inside the native binary. Statuses mean **Working native code** (with limitations stated), **Partial**, **UI-only**, or **Missing**. Server routes/source are evidence of reference behavior, not a substitute for runtime provider validation.

## Visual side-by-side plan and interpretation

Capture the **unmodified** web UI with a clean memory-only local server in headless Chromium at a 1280×800 CSS viewport and scale 1 (`scripts/capture-reference.cjs`). Put these alongside native Linux 1280×800 screenshots made by GUI CI. The reference shows its own agent shell; native includes only the Agent shell at this route. A CSS pixel is not guaranteed to coincide with an Iced physical pixel across display scaling/font renderers. An offline startup without keys does not validate chat inference. Other fixture screenshots (`visual/*import*`, `visual/*conversation*`) are synthetic; do not compare them as identical data states. When captures exist, link them below and record concrete observations rather than claiming pixel match.

## Improvement made during audit

1. **Manual import IDs:** `StageCatalogId` stages a validated exact ID in the dialog, checks it for optional import, preserves it across catalog refresh, and discards it on Cancel, route change or provider switch. No generation call or import occurs merely by staging it. Tests cover staging, refresh, cancellation and explicit import.
2. **Reasoning intervention:** while streaming, returned reasoning offers a native Thinking disclosure that can be toggled; later chunks do not override that choice. If untouched, the final Reasoning panel collapses; an explicit user-open remains open. Tests cover both paths. These are still not proof of cross-platform click or live-provider streaming behavior.
