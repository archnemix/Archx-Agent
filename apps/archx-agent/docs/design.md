# Archx AI Lab — design system

## Scope and identity

Archx AI Lab is Archnemix's AI/ML launcher. **Archx Agent** is the future six-mode chat-and-agent app; Model Training and Fine-tuning are separate future destinations. Model Monitor is hidden for now, not cancelled. Unbuilt destinations always say *Coming Later* or *In Development* and never imply a model is running. The user-supplied Archnemix mark remains the sidebar and OS icon identity. Do not copy another launcher's brand or assets.

## Color tokens

These values correspond to constants in `src/style.rs`; reuse semantic roles rather than inventing card-specific text colors.

| Role | Value | Use |
| --- | --- | --- |
| Canvas | `#000000` | True-black Chat and Settings background; rail remains subtly distinct |
| Rail | `#0D0D0D` | Sidebar behind the **transparent** logo |
| Surface | `#141414` | Featured text side and About panel |

The selected navigation pill retains the restrained graphite gradient, silver rim and subtle lower shadow. Agent and model-workspace panels use dark native gradients, with no neon or expensive blur. Measured WCAG-style contrast: muted text `#919191` against `#202020` is about **5.17:1** and against canvas about **6.35:1**; do not darken small type below this role. Logo alpha must remain intact in the sidebar; the Windows/titlebar icon can keep its black backing.

## Font roles and weight budget

Bundle licensed **Manrope** for regular body copy, navigation and utility labels; use **Space Grotesk** selectively for editorial headings and kinetic model-workspace words on Linux/Windows. On macOS, use Manrope Normal for display/labels until a variable-font weight/rendering regression is resolved; preserve the *size*-based hierarchy and accepted Agent artwork. Agent's accepted `ARCHX / AGENT` kinetic visual stays in Manrope, preserving its current character. `src/style.rs` holds reusable `DISPLAY` (Space Grotesk Medium), `DISPLAY_BOLD` (Space Grotesk Semibold) and `LABEL` (Manrope Medium) definitions. Manrope is registered on all OSes. **Static 500/600-weight instances** of Space Grotesk are registered only on Linux/Windows; the original variable font is retained for provenance. The macOS runner distorted glyph advances even with static instances, so that OS registers only Manrope **and does not select non-Normal weights** until a verified renderer fix is available. Default body remains Manrope Regular.

| Role | Size | Weight | Where |
| --- | --- | --- | --- |
| Page heading | 38px | Space Grotesk Medium | Home title; About uses 35px where necessary |
| Section heading | 24px | Space Grotesk Medium | `AI workspaces` |
| Model kinetic word | 35px | Space Grotesk Semibold | **Only one** changing emphasis word per Training/Fine-tuning tile |
| Agent kinetic display | existing 39–52px | Manrope Regular | Existing approved Agent wordmark hierarchy; do not restyle casually |
| Tile name | 17px | Space Grotesk Medium | Inert destination names below panels |
| Body / nav | 14–16px | Manrope Regular / navigation Medium | Descriptions and navigation |
| Eyebrow / status | 11px, occasionally 10px in constrained panel footers | Manrope Medium | Short uppercase labels, never long instructions |

Do **not** bold every heading, caption or navigation row. Semibold is reserved for the two model-workspace kinetic words; page and section headings use Medium, leaving the Agent's larger wordmark and the selected navigation as primary emphasis. Keep short lines and whitespace around large display type; don't pack stage labels into a corner.

## Spacing, layout and motion

`src/style.rs` defines a 4px micro increment and reusable major spacing steps **8 / 16 / 24 / 36px** (`SPACE_1..4`). Use 4px for within-label optical gaps, 8px between closely related words, 16px for tile internals and tile-to-label rhythm, 24px for adjacent text blocks, and 36px between major page sections. The expanded sidebar remains 220px wide; the supplied transparent mark displays at 116 × 116 without a black square. The compact rail is a different 92px icon-only layout with a larger 72 × 78 transparent mark, not truncated text. Major surfaces have rounded 10–15px corners and one-pixel borders. At 1024px-wide macOS runner captures, the shelf may continue below the fold but stays scrollable.

The Agent hero and tile retain the synchronized six-mode text/marker cycle (1500ms on Home, paused on About). Training and Fine-tuning are visually distinct **typographic labs**, not static captions or 3D objects: **Model Forge** communicates creating/training a model; **Refinement Studio** communicates adapting an existing one. On hover only, a central editorial word and a three-part phase marker change every 700ms. The words (`DESIGN / TRAIN / EVALUATE` and `SELECT / ADAPT / VALIDATE`) are conceptual, **not live operational progress**; pointer exit resets to the first state. Cards remain inert and labelled Coming Later. Avoid continuous idle animation for these two model tiles. Reduced-motion and RAM/CPU preference settings remain future requirements, not silently implemented.

## Cross-OS review gate

After a GUI change, build/run on Linux, Windows, and macOS; inspect Home, About, Agent frozen phases and both model-card hover phases. Put screenshots only in `Docs/Test_Results/Unreleased/visual/` and tests/build/PE logs only in `Docs/Test_Results/Unreleased/non_visual/`. Static phase captures demonstrate distinct render states but cannot establish live motion smoothness or actual mouse movement; user hands-on review remains required. ## Agent workspace and Lab Settings UI preview

The Lab navigation remains the global shell. Agent has a distinct inner conversation rail and restrained six-mode chips; selecting a mode only changes an **unsent draft's UI preview**, not tools, inference, or prior-message conversion. Temporary drafts and their unsent text are clearly marked session-only; the composer accepts typing, but **Send remains unavailable** without a model and Enter does not submit. Settings lives in the Lab rail, not as a per-Agent page. Memory Light / Memory Heavy / Custom are UI-only choices with an explicit no-effect message until there is a real loader and persistence. Custom previews Agent only; unavailable future destinations cannot be preloaded. Reuse the black/silver palette, spacing and font roles above; do not alter the approved launcher Agent animation.

## Shared navigation density

The Lab rail defaults to an expanded 220px icon+label navigation with the transparent 116px Archnemix mark and muted unavailable destinations. Collapse switches the **layout** to an intentional 92px icon rail, not just a smaller width: a 72×78 transparent brand mark, two primary icon actions near the top, divider and About/Settings utility icons near the bottom, and a fixed-size icon expand control integrated at the foot. Each route uses a locally bundled 22px outline glyph (license in `assets/icons/`) and a right-side hover tooltip. The active route alone receives a restrained 52px charcoal/silver tile, never a full-width pill. Both views keep the same session-only navigation state; native buttons remain keyboard reachable, though Iced tooltip focus/screen-reader labeling needs separate accessibility verification. Do not copy the reference mockup's logo, colors, pages or web code.

Settings has a persistent in-page 190px category rail for **Providers / Models / Runtime memory / Storage & display / Agent memory** and a scrollable active detail area. These are only the sections the native app actually supports; the supplied HTML/CSS is a layout reference, not a source of new product capabilities. For Chat, sending requires an explicit click and a manually chosen model; historical UI-only wording elsewhere in this document describes its earlier milestone, not the current provider trial. Cross-OS screenshots must include expanded/compact Home, Agent and Settings, plus Models and Custom preview. Inspect visual clipping after every GUI change; static captures do not verify hover, actual clicks or OS vault behavior.

## Chat workspace redesign — user reference is binding (2026-11-09)

The previous 6–7 rows of mode/provider/model/stream/config text are **rejected**. Model/provider choice belongs in **one compact topbar button** opening a searchable two-column menu; mode switching is compact, never another full-width row. Only the actual conversation, not settings, owns the main viewport. Do not import browser scripts, server-backed persistence, web tools, unapproved actions or its authentication claims.

Reference-specific token plan (the Chat destination only): pure canvas `#000000`; sidebar `#0B0B0B`; menus/composer `#101010`; user bubble `#161616`; neutral edges `#2C2C2C`; text `#F4F4F4` with silver `#B2B2B2`. Manrope is body; Space Grotesk stays for established launcher headings only. Target a max-860px conversation/composer column at wide widths, centered within the available Chat main area. Desktop layout: `Lab rail | chat-history rail | [topbar: model picker ... mode] / centered scrollable avatar+message rows / narrow bottom composer`. On a shorter 1024×640 capture, preserve the composer and scroll the message list; no floating opaque settings rows should obscure replies.

Reasoning: a **small collapsible subdued panel inside the assistant message body**, not a prominent button above a boxed Markdown card. It appears only when the provider returns reasoning text; its content is inert Markdown and must not be treated as permission to execute tools or expose private vendor reasoning not provided by the API. A user message is a modest rounded bubble beside a tiny avatar; assistant content is unboxed Markdown beside an inverse avatar. No invented timestamps, token costs, prompt stack, web-search toggle, branch controls, or API debugging UI. The user's supplied browser CSS is the visual spec; the native implementation uses Iced widgets and its platform limits, so exact HTML/CSS pixel identity is not promised.

## Agent Chat scroll and catalog import refinement (2026-11-09)

For live conversations the native Iced 0.14 `Scrollable` uses a bottom anchor and tracks the viewport's bottom-relative offset. A 32px proximity threshold follows streaming updates only while the reader is at the tail; scrolling away reveals **Jump to latest**, and returning to a draft restores its prior follow/reading state. Screenshot-only fixtures keep their top-anchored capture behavior. This is a native approximation of the reference's follow-until-intervention rule; mouse-wheel, touchpad, keyboard and programmatic scroll should still be exercised manually on each OS.

The catalog dialog now offers **Add only verified models**. It counts an ID as verified only when an explicitly confirmed generation probe contains the configured expected word; returned text without that word is a failure. Changing the word invalidates prior results. An eligible-count label and disabled add control avoid implying untested items passed. Checked failed IDs remain selected for a later test when verified-only import adds passing IDs. Fixed-provider probes measure elapsed time and retry an explicit HTTP 408/429/5xx rejection once after 250ms, but never retry an ambiguous transport timeout that may have already been billed. One consent confirmation covers up to two potentially billable attempts per selected ID, each with 256 output tokens. The dialog still runs probes **sequentially** (not the web app's eight-worker pool); Stop aborts the active task, and a screenshot fixture proves only rendered state, not live provider behavior.

Reference: `internels/reference/web/archx-agent/UI-RULES.md` (4/8/16/24px relationship rhythm, 15px body). Online professional guidance informed the hierarchy and alignment changes: [Apple Layout](https://developer.apple.com/design/human-interface-guidelines/layout) recommends aligned grouping, content margins and progressive disclosure; [Apple Typography](https://developer.apple.com/design/human-interface-guidelines/typography) recommends size/weight/color hierarchy and legible text; [W3C WCAG 2.2 target-size guidance](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) specifies 24×24 CSS pixels or qualifying spacing for web pointer targets. Those sources are guidance, **not a claim of native platform accessibility certification**. The dialog's title is 19px, data 12–13px and secondary status 11px; the list is adaptively sized and separated by 8px control gaps and 20px dialog margins. Check short-window clipping and visual comparisons on all three OSes before calling the layout verified.

## Source-audit refinements (current)

The latest native Settings has a page heading and a 200px in-page category rail to reproduce the 1.9.0 hierarchy (only native-implemented sections are enabled); the models pane does not pretend to provide the web reference's enabled/disabled groups. The Add models overlay is stacked over the whole Agent window, with a 680px maximum card width, rather than centered inside the settings pane. The dialog stages manual IDs as checked candidates without importing/testing until an explicit action; Cancel discards them, and a catalog refresh retains staged manual IDs. Native only-verified remains deliberately stricter than the web only-working: untested IDs are **excluded**, and testing never auto-starts on a toggle due billable requests. A small button hierarchy makes New chat and final import primary actions; the rest of the controls are quieter.

The returned-reasoning disclosure opens while streaming by default, lets the reader override that state and preserves an explicit user-open after completion, otherwise collapsing. It still re-renders Iced Markdown blocks rather than preserving web DOM identity or independent code/table scroll state. See `Docs/Test_Results/Unreleased/Reference_Native_Audit.md` for a source-backed comparison, controlled screenshot links, all known major gaps, and test provenance.
