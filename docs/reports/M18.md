# M18 completion report - Embedding and retrieval evaluation

> **Historical report.** This describes its recorded checkpoint, including old counts
> and limitations. For current status, read [the audit](../AUDIT.md),
> [progress](../../PROGRESS.md) and [known gaps](../../GAPS.md).

## 1. Objective

Give Archx a real embedding pipeline: create, store and query vectors with correct model
identity, keep working (degraded and honest) when vectors are missing, and *measure*
retrieval quality instead of asserting it.

## 2. What was built

* `helpers/vectors.py`: float32 pack/unpack, normalisation, cosine/dot, `top_k` with
  threshold and dimension-mismatch refusal, byte-size accounting.
* `adapters/embedding_runtime.py`: `HashEmbeddingProvider` (offline,
  `archx-hash-v1`, 256-dim, word unigrams/bigrams + char trigrams, `semantic=False`),
  `HttpEmbeddingProvider` (OpenAI-compatible `/v1/embeddings`, key registered as a secret,
  dimension discovered then enforced), `SentenceTransformerProvider` (optional, raises
  `UnsupportedOperationError` when the package is absent), `build_provider()`.
* `managers/embeddings.py`: upsert/search/backfill/purge/status, per-model identity,
  checksum staleness, `memory_scores()` batch API for hybrid retrieval,
  `embed_conversation()`.
* Schema v9: `embeddings` (unique on owner+model), `retrieval_runs`.
* `MemoryManager` integration: `embedding_index` parameter, `embedding_state`
  (`awaiting`/`embedded`/`failed`), `set_embedding_state()`, hybrid re-scoring, honest
  `degraded`/`degraded_reason` when vectors are missing. Keyword matching rewritten to
  token `LIKE ... ESCAPE` OR-clauses (the full-phrase form could not match
  `"database locked"` against `"Database is locked"`).
* `application/retrieval_eval.py`: precision@k, recall@k, MRR, nDCG@k with exponential
  gain, three modes (keyword baseline / semantic only / hybrid), per-query detail,
  markdown + JSON reports.
* `data/retrieval_set.json`: 20 labelled memories, 12 graded queries (1-3).
* CLI: `embeddings status|backfill|embed-conversation|search|purge` and
  `eval retrieval --dataset ... --k 5 --out report.md --json [--no-scratch]`
  (default: a throw-away scratch home so evaluation never pollutes real memory).

## 3. How it was verified

* `tests/test_embeddings_m18.py` - 29 tests: vector maths and thresholds; hash provider
  determinism and dimension bounds; HTTP provider against a real local HTTP server
  (success, dimension discovery, dimension change rejected, malformed body, count
  mismatch, 500); remote provider requires explicit opt-in; upsert/re-embed/stale
  detection; cross-model refusal; search threshold behaviour; batch scores; purge;
  conversation embedding; metric implementations against hand-computed values; a full
  evaluation run producing a markdown report.
* Real run (`docs/VERIFICATION.md`): `embeddings status` reports
  `local-hash model=archx-hash-v1 dim=256 semantic=False`; backfill embedded 7 memories;
  `embeddings search "which database do we use for storage"` returned the storage
  decision first (0.378), the locking issue second, the WAL note third.
* Measured quality (`docs/RETRIEVAL_EVAL.md`), 20 items / 12 queries / k=5:

| mode | precision@5 | recall@5 | MRR | nDCG@5 |
|------|------------|----------|-----|--------|
| keyword | 0.379 | **0.764** | 0.681 | 0.637 |
| semantic | 0.283 | **0.847** | 0.896 | 0.839 |
| **hybrid** | **0.396** | 0.806 | **0.917** | **0.850** |

## 4. Decisions and what they cost

* **Hybrid is relevance-only.** Recency and access-count bonuses were implemented first
  and made ranking worse (nDCG 0.70 vs 0.84 for semantic alone); they are excluded from
  the blend and shown separately. Cost: a recently added memory is not boosted in search.
* **`--threshold 0` is ranking mode.** The default 0.62 cosine floor is for "show related
  items"; retrieval must return a ranked top-k even when absolute similarity is low.
  Confusing the two produced empty results at first; the CLI now documents both.
* **Hash embeddings are labelled non-semantic everywhere** (status output,
  `docs/RETRIEVAL.md`, this report). The measured numbers are an upper bound for
  same-vocabulary queries and must not be presented as semantic quality.
* **`VultronRetrieverPrime-Qwen3.5-8B` was rejected with reasons** (visual-document
  multi-vector retriever, 8.4B, page images, MaxSim) and the fallback path was written
  down before choosing a provider.
* **Scratch-home evaluation by default.** Evaluating against the live workspace changes
  the corpus under the user's feet; `--no-scratch` exists for deliberately measuring the
  user's own memory.

## 5. Limitations

* No real semantic model could be exercised here: HF is unreachable and no weights exist
  locally. The `sentence-transformers` and `http` providers are implemented and the HTTP
  one is integration-tested against a local server, but no hosted model was called
  (correctly: remote embeddings require explicit opt-in and that opt-in was not given).
* Brute-force scan; documented ANN threshold ~200k embedded objects.
* No incremental re-embedding scheduler yet: `embeddings backfill` is manual (M26 will
  schedule it).
* Retrieval quality for non-English text is unmeasured.

## 6. What this unlocks

M19 uses these vectors inside the context budget (memory in-context selection). M20/M21
can treat "does this provider actually embed?" as a verified capability instead of a
label. M24/M27 can reuse `retrieval_runs` for search history.
