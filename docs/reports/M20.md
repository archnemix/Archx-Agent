# M20 completion report - Cloud provider catalogue and privacy metadata

> **Historical report.** This describes its recorded checkpoint, including old counts
> and limitations. For current status, read [the audit](../AUDIT.md),
> [progress](../../PROGRESS.md) and [known gaps](../../GAPS.md).

## 1. Objective

Support remote providers without ever sending a conversation, file, memory or project
detail off the machine silently: a catalogue that keeps vendor claims separate from
verified facts, a privacy view the user can actually read, an explicit consent gate, and
observable availability, usage and cost.

## 2. What was built

* `managers/providers.py`: provider catalogue (templates for OpenAI / Anthropic / Google /
  local OpenAI-compatible servers, plus arbitrary custom endpoints), secret references
  (`secret://env/NAME`, never a literal key), derived locality, privacy claims vs user
  confirmations, versioned consent, availability probes, quotas, usage.
* `helpers/exceptions.py`: `ConsentRequiredError`, `PrivacyUnknownError`.
* `application/workspace.py`: `Workspace.assert_remote_allowed` - the single enforcement
  point, called from `runtime_for` - plus `record_usage` attribution and an honest
  `model_choice_explanation.local` derived from the endpoint.
* Schema v12: provider privacy/consent/pricing columns, `provider_checks`, usage index.
* CLI: `providers catalogue|add|list|show|confirm|consent|revoke|enable|disable|check|quota|usage|privacy|remove|stats`
  with a new exit code `3` (degraded) for failed probes.
* `scripts/openai_protocol_stub.py`: a real HTTP server speaking the OpenAI chat protocol,
  used for integration testing where no model weights exist. Replies are prefixed
  `[PROTOCOL-STUB]`.
* `scripts/acceptance_m20.sh`, `scripts/bootstrap.sh`, `docs/PROVIDERS.md`.

## 3. How it was verified

`tests/test_providers_m20.py` - 30 tests:

* **catalogue/registration**: templates carry a claim source; loopback detection;
  cloud providers start blocked with privacy unknown; local providers need no consent;
  literal API keys refused; `kind=local` with a non-loopback URL refused; duplicate names
  refused; a confirmation that contradicts a loopback URL refused.
* **consent**: requires confirmed privacy first; consent is versioned; revocation blocks
  again; an old consent version forces reconfirmation; a disabled provider is blocked but
  keeps its privacy data; the privacy report explains each provider.
* **availability** (against a real HTTP server): reachable with model count and latency;
  401 → `auth_failed`; 500 → `unreachable`; unknown route → `model_missing`; closed port →
  `unreachable`; the `Authorization` header is actually sent from a secret reference; an
  unresolvable secret → `auth_failed` with the reason.
* **usage/quota**: aggregation, cost only with user-supplied prices, per-day breakdown,
  quota enforcement on requests and tokens.
* **workspace enforcement**: remote model refused in local-only mode; refused without a
  registered provider; refused while privacy unconfirmed; refused without consent;
  allowed after all three; loopback allowed without consent; usage attributed to the
  provider.
* **tracing**: every privacy action is traced, and no key material appears in event
  payloads.

`tests/test_cli.py::TestCliProviders` - 5 end-to-end tests through the console script,
including a full local-provider chat against a real HTTP stub with usage numbers read back
from the database.

Real acceptance: `scripts/acceptance_m20.sh` (transcript in `docs/VERIFICATION.md#m20-acceptance`).
Full suite: **251 passed, 0 failed, 0 skipped** on Python 3.11.2.

## 4. Decisions and their cost

* **Three gates for remote data** (policy switch + registered provider + confirmed privacy
  and consent). Cost: onboarding a cloud model takes four deliberate commands. That is the
  intended cost; a one-command path would defeat the point.
* **Locality derived from the URL.** The first implementation trusted a label and the
  acceptance run caught a `local-http` label pointing at `api.openai.com` being reported as
  local. Now the host decides, and a `kind=local` entry with a public URL is refused.
* **Vendor claims are stored as claims, with their source, and `verified = 0`.** Cost: the
  CLI prints "vendor claim" instead of a reassuring "leave device: no". That honesty is
  the feature.
* **No default prices.** Cost estimates exist only where the user supplies prices; a stale
  built-in price list would produce confident wrong numbers.
* **Quotas enforced locally** rather than delegated to the provider.
* **A real protocol stub instead of a mock.** `ScriptedRuntime` never touched a socket; the
  stub proves auth headers, request shape, usage parsing and reply storage over HTTP.

## 5. Limitations (recorded, not hidden)

* No vendor API was called: no keys exist in this environment. Privacy claims and prices
  are transcriptions, flagged as unverified; region/residency is free text and not
  enforced.
* `providers check` only probes `/models`; a provider that lists models but fails
  completions is discovered at the first request (and recorded as a failed usage event).
* Cost estimates ignore cached-token discounts, batch pricing and minimum charges.
* No per-project consent scoping yet: consent is per provider, workspace-wide.
* No credential rotation flow; `secret://` references are resolved at use time, so
  rotating the underlying environment variable requires no Archx change, but Archx does
  not verify expiry.

## 6. What this unlocks

* **M21 (capability-safe router)**: the router can now prefer local, verified-capable
  models and treat "remote" as an explicitly consented, quota-checked fallback rather than
  a flag.
* **M22 (permission centre)**: consent is the first real permission decision, with a
  versioned record, a trace entry and a stable error code to surface in an approval UI.
* **M37 (remote compute)** and **M39 (automations)**: both will need "may this leave the
  machine, under which terms, how much has it cost" - implemented once here.
