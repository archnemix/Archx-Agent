# M27 completion report - Simple Mode and unified search

> **Historical report.** This describes its recorded checkpoint, including old counts
> and limitations. For current status, read [the audit](../AUDIT.md),
> [progress](../../PROGRESS.md) and [known gaps](../../GAPS.md).

## 1. Objective

The app by this point had nine surfaces that stored something: conversations, six kinds of
memory, tasks, workflows, projects, artifacts, tools and the files a user works on. Each had
its own command. A person asking "where did I write about database locks" had to know that
the answer might be in `conv search`, `memory search`, `tasks list`, `agent list` or a file,
and had to try each one. And a person who did not want to learn any of those commands had no
entry point at all.

The milestone asked for two things that sound different and are the same problem: **one
search** across everything, and a **Simple Mode** that turns plain language into one of a
small number of operations. The constraint that shaped every decision: do not build a second
store, a second index, or a second permission path. A friendly front door that quietly
bypasses the permission centre would be the most dangerous thing in the product.

## 2. What was built

* **`application/search.py` - `SearchService`.** One query, eight sources (`conversation`,
  `memory`, `task`, `workflow`, `project`, `artifact`, `file`, `tool`), each read from the
  manager that already owns it. `TasksManager.search` and `WorkflowsManager.search` were
  added so the task and workflow sources reuse their managers' scoping and ordering rather
  than re-deriving it from raw rows.
* **One scoring function for every source.** `score_text` builds terms (2+ characters,
  deduplicated, at most eight, longest first), searches `title + "\n" + text`, scores
  coverage (full coverage ⇒ at least `1.0`), adds `0.5` for the exact phrase and `0.75` for a
  term in the title. Merge order is `(-score, -KIND_WEIGHT[kind], title)`, so a deliberate
  memory outranks a file that happens to contain the word but never overrides a better score.
* **Honest reports.** `SearchReport` carries `hits`, `counts`, `scanned`, `skipped`,
  `degraded`, `elapsed_ms` and `total`. A source returns `(hits, note, consumed)`; a note is
  either a `degraded` entry (partial answer, with the reason) or a `skipped` entry (not
  looked at, with the reason). A source that raises is caught, recorded and skipped - the
  other sources still answer.
* **File search with the same boundary as tools.** Only inside `ws.tool_roots()`, never
  dot-directories, never `SKIP_DIRS`, never a symlink escape, never a NUL-containing file,
  never larger than `search.max_file_bytes`, never more than `search.max_files`, and the
  truncation is reported. Search writes nothing at all - no counters, no trace events.
* **`application/simple.py` - `SimpleMode`.** A closed intent set
  (`chat | search | recall | remember | status | workflow | help | quit`), `detect_intent`
  returning `(intent, why)` where `why` is printed to the user, and `SimpleResult` carrying
  `headline`, `detail`, `next_step`, `simulated` and structured `data`.
* **Four refusals as results, not exceptions.** No model → an explanation plus
  `models add-http`; a missing grant → `approvals approve ap_…` and exit `4`, with no grant
  created; a checkpoint → `agent run … --approve`; a model step with no model → a named stop
  rather than a traceback.
* **`remember` is a real memory.** `permanent`, category `preference` only for
  unambiguous wording (`always`, `never`, `from now on`), `provenance.mode = "simple"`, the
  existing duplicate detection intact - a second attempt is reported, not silently swallowed.
* **CLI.** `search QUERY [--kind …] [--limit] [--per-source] [--project] [--conversation]
  [--no-files]`, `simple ask|status|help`, and a bare `simple` REPL that keeps one
  conversation, explains every line and survives a refusal.
* **Config.** `search.default_limit`, `search.per_source`, `search.include_files`,
  `search.max_files`, `search.max_file_bytes`, all honoured by the CLI and by Simple Mode.
* **`docs/SIMPLE_MODE.md`** and **`scripts/acceptance_m27.sh`** (23 self-checking assertions,
  including an approval round trip and a spent one-shot grant).

## 3. How it was verified

* **109 tests** in two new files: `tests/test_search_m27.py` (42) and
  `tests/test_simple_m27.py` (67). Search covers scoring (coverage, phrase, title, case,
  punctuation, kind weights), every source, every control (kinds, limit, per-source,
  conversation scope, file switch-off, no matches, determinism, degradation, serialisation),
  the file safety rules (binary, oversize, noise directories, nesting) and the CLI
  (`--json`, `--kind`, `--no-files`, no matches). Simple Mode covers 18 natural-language and
  10 slash-command classifications, every intent against real data, the three refusal paths,
  the duplicate report, `status` with and without a model, serialisation, and the installed
  console script (`ask`, `--json`, `remember`, `status`, `help`, the piped REPL, a usage
  error and a missing model).
* **Full suite: 806 passed, 0 failed, 0 skipped** (Python 3.11.2, 153s; junit xml:
  `tests=806 failures=0 errors=0 skipped=0`).
* **Real acceptance** (`scripts/acceptance_m27.sh`, exit 0, 23/23 checks) on a fresh home:
  one `search database` returned a memory, two conversations, two tasks, a workflow and a
  file, named the per-source counts, printed the `keyword-only` degradation and did not read
  a binary file; `--no-files` appeared as a skip rather than an empty result; `simple ask`
  answered the same question with its reason; `remember` stored a fact, categorised a
  preference, and reported a duplicate; `status` read real counts and labelled the test
  double; a `summarise-file` workflow refused for lack of `fs.read` with exit `4` and an
  approval id, created **no** grant; the printed `approvals approve` command created exactly
  the requested grant, the approved run completed, and the one-shot grant was then spent so
  the next identical request refused again. Transcript:
  `docs/VERIFICATION.md#m27-acceptance-transcript`.

## 4. Decisions and their cost

* **No index.** Search scans the managers on every query. The cost is linear time and a
  file-count budget; the benefit is that results can never disagree with `memory list`, and
  there is no second schema to migrate. `GAPS.md` records the scale at which this stops
  being acceptable.
* **One scoring function, kind weights only for ties.** A source cannot express its own
  relevance. The benefit is that "why is this first" has exactly one answer, and the score is
  printed.
* **A broken source degrades instead of failing.** A systematic bug in one manager shows up
  as a note rather than an error. That is a deliberate trade: failing the whole search because
  the embedding index is missing would break the feature in the most common setup.
* **File search inherits the tool roots.** Files outside `ws.tool_roots()` are invisible to
  search. The cost is that this is not a desktop search; the benefit is that the front door
  has no read primitive that `fs.read` lacks.
* **Simple Mode is not an agent.** Rules, not a model, decide the intent. That means
  "tell me about X" is chat while "where did I write about X" is search, and a user can
  disagree - but the printed `why` makes the disagreement visible instead of mysterious, and
  the app can say "no model is configured" without needing a model to say it.
* **Refusals are results.** A refusal carries the exact command that would unblock it and an
  exit code (`4`) a script can test. The cost is an extra result shape to maintain; the
  benefit is that the most common failure in the whole product became the clearest message in
  it.
* **`remember` writes to memory, not to a notes table.** Inference of `preference` from a few
  words will sometimes be wrong; the fix is `memory edit`, and the alternative was a second
  memory system that nothing else could find.
* **`search.default_limit`/`per_source` live in config and on the flag.** The CLI passes
  `None` when the flag is absent so one source of truth decides, which is also why the
  defaults are described in `--help` as "default: search.default_limit".

## 5. Limitations

* Keyword-only outside memory: no stemming, no synonyms, no typo tolerance (`GAPS.md`).
* Linear scan; no index, no incremental updates, no result caching.
* File search reports aggregate counts, not per-file skip reasons.
* `status` shows counts and the chosen model, not a diagnostic; deeper questions point at
  `trace` and `tasks show`.
* A refusal still records a failed task, so repeated attempts make `tasks list` noisy.
* An approval keeps the approval's scope: a `once`, conversation-scoped grant authorises one
  run in one conversation, so the same request afterwards asks again.
* Simple Mode cannot chain intents ("remember this and then run that"); one line, one intent.

## 6. What this unlocks

* **M28 Researcher Mode** gets its entry point: a research run is a sequence of searches
  whose results are already ranked, scoped and honestly sourced, and each step is an M25
  workflow step that can be queued as an M26 job.
* **M29 GUI** gets one query API (`SearchService`) and one front-door API (`SimpleMode`)
  instead of a screen per surface.
* **M30 Learning Mode** and **M31 coding workspace** can reuse file search inside the same
  tool roots for "where is this defined" without inventing a second file walker.
* **M32 experimental mode** and **M40 hardening** get a read path with a tested
  never-writes property, and a boundary (tool roots) that a fuzz test can attack.
