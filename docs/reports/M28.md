# M28 completion report - Researcher Mode

> **Historical report.** This describes its recorded checkpoint, including old counts
> and limitations. For current status, read [the audit](../AUDIT.md),
> [progress](../../PROGRESS.md) and [known gaps](../../GAPS.md).

## 1. Objective

Everything built so far is a store with a surface: conversations, memories, tasks,
workflows, projects, artifacts, tools, and (M27) one search across them. A person can ask
"where did I write about database locks" and get an answer. They could not ask **"what do I
actually know about database locking, and what evidence is that based on?"** - a question
whose answer must distinguish reading from guessing.

Researcher Mode is the first milestone that produces a *document* rather than a record. That
makes it the first one that can lie convincingly: a plan-shaped list of headings, a
confident paragraph, a citation to a page nobody opened. The milestone was therefore defined
by five refusals, not by a feature list:

1. do not present a plan whose author is unknown;
2. do not cite a source you did not read;
3. do not drop a source that failed - record it;
4. do not keep prose that cites nothing;
5. do not call an empty run a success.

Everything else - `net.fetch`, the extractive answer, the task and artifact wiring - exists
to make those refusals cheap enough to keep.

## 2. What was built

* **`managers/research.py` - the record.** `research_runs` (question, mode, plan,
  `planned_by`, status, report, report path, coverage, evidence count, limitations, error,
  model, settings) and `research_sources` (kind, ref, title, publisher, excerpt, status,
  error, sha256, bytes, relevance, credibility, stance, claims, subquestion). Four write
  kinds, journaled like every other mutation: `research.create`, `research.update`,
  `research.source`, `research.delete`. Schema v18 extends the v8 tables - the migration is
  additive and re-runnable.
* **`adapters/net_fetch.py` + the `net.fetch` tool.** A capability that had been declared
  since M22 and deliberately unimplemented. http(s) only, no credentials in a URL,
  loopback/private/link-local/reserved addresses refused (including `169.254.169.254`)
  unless `tools.fetch_allow_private_hosts` is set, manual redirects (each hop re-resolved and
  re-checked, at most `tools.fetch_max_redirects`), a byte cap with `truncated`, a text
  content-type allowlist, HTML-to-text with the `<title>` kept, and a sha256 of the body.
* **`application/researcher.py` - the pipeline.** `plan` (validated model JSON, or
  deterministic rules, or the user's subquestions), `gather_local` (SearchService over six
  kinds), `gather_web`, `judge` (stance and relevance; a quote that is not in the excerpt is
  dropped), `synthesize` (extractive answer, `[S<n>]` per line, uncited model prose moved to
  its own section), `verify` (a classmethod, callable on any report), `_write_report`.
* **Facet assignment by vocabulary.** A local document is assigned to the subquestion it
  answers: the topic subquestion wins unless the document contains vocabulary a facet added
  and the question did not. This is what makes "no source addresses this facet" a finding
  rather than an artefact of heading order.
* **No self-citation.** The run's own task and its planning conversation are excluded from
  local search, so a research run cannot cite itself into completeness.
* **Task and artifact.** Every run creates a `research` task, and the report file is attached
  as an artifact with its checksum, so `tasks show`, `versions` and `research report`
  describe the same bytes.
* **Third job kind.** `jobs submit research "…"` queues the same run through M26's queue;
  `_run_research` raises on an empty question and on a run that did not complete, so a failed
  research job is a failed job.
* **CLI.** `research run|list|show|sources|report|verify|search|stats|delete`, with
  `--mode`, `--url`, `--urls-from`, `--subquestion`, `--format`, `--out`, `--no-model`,
  `--allow-private-hosts`; exit `0` completed, `3` incomplete or unverified, `4` capability
  needed, `2` usage, `1` failed.
* **Config.** `paths.research`, eight `research.*` keys and five `tools.fetch_*` keys.
* **`docs/RESEARCH.md`** and **`scripts/acceptance_m28.sh`** (30 self-checking assertions,
  including a real local HTTP site served by the script, an approval refusal, a spent grant,
  a 404, a binary page, a private-address refusal and a queued job).

## 3. How it was verified

* **97 tests** in `tests/test_research_m28.py`, in eleven classes: the fetch adapter's guards,
  the tool and its approval, the manager's CRUD and conflicts, planning (rules, user, model
  JSON, malformed JSON), judgement parsing (fabricated quotes, out-of-range relevance,
  invalid stance), local runs, web runs against a module-scoped `ThreadingHTTPServer`, mixed
  runs, `verify`, the report, the CLI, job-through-queue, and seven targeted guards (metadata
  IP, loopback, excerpt window, facet vocabulary, citation numbering restart, `verify` exit 3).
* **903 tests** in the full suite, 0 failures, 0 skipped (173 s). Two pre-existing tests were
  updated for intentional behaviour changes: `JOB_KINDS` now includes `research`, and the
  "unknown capability" probe in the M22 tool tests moved to `http.request` because
  `net.fetch` is real.
* **`scripts/acceptance_m28.sh`**: 30 checks, exit 0, against a fresh home, the installed
  console script, and a real HTTP server on a random port.

## 5. Bugs the milestone found (and fixed)

* `interfaces/cli/main.py` used `NotFoundError` without importing it, so `research show
  rs_nope` raised `NameError` and exited 1 instead of 2. Caught by a CLI test, not by hand.
* `research verify` compared report labels (`[S1]`) against *row ids* (`S7`), so every check
  failed on a run whose sources were not numbered from 1. The fix is `citation_numbers()`,
  shared by `sources`, `verify` and the report writer, and the acceptance run now proves the
  labels and the check agree.
* The acceptance script's first version found the hard part and missed the easy one: its
  inline HTTP server was never started, so six checks failed with "Connection refused" and
  looked like a researcher bug. It now refuses to continue if the site did not come up.
* Two exit-code assertions in that script were checking the JSON, not the exit code. They now
  capture `$?` - the difference between claiming an exit code and checking one.

## 6. Deliberate limits

Recorded in [GAPS.md](../../GAPS.md) and [RESEARCH.md](../RESEARCH.md): no crawler and no
search engine (seed URLs are the user's), no PDFs or office documents, no credibility
rating, stance requires a model, relevance is term overlap, no resume of an interrupted run,
`verify` checks form and not truth, `net.fetch` has no robots.txt or rate limiting, and the
report is only as good as the excerpt window.

## 7. Next

M29 (GUI core workflows) should be a client of `SearchService`, `SimpleMode` and
`ResearchRunner` - the same services, not a second implementation. The temptation with a
desktop UI is to write "just a quick fetch" in the view layer; M28 is the milestone that
makes the cost of that visible, since every network path now carries a capability, an
approval and a recorded run.
